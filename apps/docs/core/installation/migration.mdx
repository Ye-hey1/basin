## What changed in v2.6.0

This release replaces the separate `api` and `web` containers with a single `basin` container. nginx runs on port 5173 and proxies `/api/` requests to the internal Node API. Everything else (the database, volumes, environment variables) works the same.

Three areas require changes when upgrading:

1. Docker Compose: replace the `api` and `web` services with `basin`
2. Environment variables: `BASIN_API_URL` and `DATABASE_URL` are now optional
3. Helm chart: all `api.*` and `web.*` values moved under `basin.*` (chart version 0.3.0)

---

## Docker Compose

### Before

```yml
services:
  postgres:
    image: postgres:16-alpine
    env_file:
      - .env
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    restart: unless-stopped

  api:
    image: ghcr.io/usebasin/api:latest
    ports:
      - "1337:1337"
    env_file:
      - .env
    depends_on:
      - postgres
    restart: unless-stopped

  web:
    image: ghcr.io/usebasin/web:latest
    ports:
      - "5173:5173"
    env_file:
      - .env
    depends_on:
      - api
    restart: unless-stopped

volumes:
  postgres_data:
```

### After

```yml
services:
  postgres:
    image: postgres:16-alpine
    env_file:
      - .env
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U \"$${POSTGRES_USER:-basin}\" -d \"$${POSTGRES_DB:-basin}\""]
      interval: 10s
      timeout: 5s
      retries: 5

  basin:
    image: ghcr.io/usebasin/basin:latest
    ports:
      - "5173:5173"
    env_file:
      - .env
    depends_on:
      postgres:
        condition: service_healthy
    restart: unless-stopped

volumes:
  postgres_data:
```

Remove the `api` and `web` service blocks and add the `basin` service. The `postgres` service is unchanged except for the added healthcheck, which `basin` waits for before starting.

## Environment variables

### BASIN_API_URL is now optional

Previously both `BASIN_CLIENT_URL` and `BASIN_API_URL` were required. Now `BASIN_API_URL` is derived automatically from `BASIN_CLIENT_URL`:

```
BASIN_API_URL = BASIN_CLIENT_URL + "/api"
```

Remove `BASIN_API_URL` from your `.env` unless you need to override it (for example, when a reverse proxy changes the API path).

**Before:**
```env
BASIN_CLIENT_URL=https://basin.example.com
BASIN_API_URL=https://basin.example.com/api
```

**After:**
```env
BASIN_CLIENT_URL=https://basin.example.com
# BASIN_API_URL is set automatically to https://basin.example.com/api
```

### DATABASE_URL is now optional

For the bundled image, `DATABASE_URL` is derived from `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, and the default Compose hostname if you leave it unset:

```
postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}
```

If you were setting `DATABASE_URL` explicitly with the same values, you can remove it.
Keep it if you use an external database, a non-default hostname, or a host-native API process that should connect through `localhost` instead of the Compose hostname.

**Before:**
```env
POSTGRES_DB=basin
POSTGRES_USER=basin
POSTGRES_PASSWORD=changeme
DATABASE_URL=postgresql://basin:changeme@postgres:5432/basin
```

**After:**
```env
POSTGRES_DB=basin
POSTGRES_USER=basin
POSTGRES_PASSWORD=changeme
# DATABASE_URL is derived automatically
```

### AUTH_SECRET fallback behavior

If `AUTH_SECRET` is not set, the container generates a random 64-character hex secret at startup and prints a warning to stderr. This means sessions will not survive container restarts.

Set a stable secret to avoid losing active sessions on restart:

```bash
openssl rand -hex 32
```

```env
AUTH_SECRET=your_generated_secret_here
```

## Helm chart (0.2.0 → 0.3.0)

Chart version 0.3.0 is a breaking change. All `api.*` and `web.*` value keys have moved under `basin.*`.

### Changed value keys

| Old key | New key |
|---|---|
| `api.image.repository` | `basin.image.repository` |
| `api.image.tag` | `basin.image.tag` |
| `api.image.pullPolicy` | `basin.image.pullPolicy` |
| `api.service.type` | `basin.service.type` |
| `api.service.port` | `basin.service.port` |
| `api.resources` | `basin.resources` |
| `api.env.clientUrl` | `basin.env.clientUrl` |
| `api.env.authSecret` | `basin.env.authSecret` |
| `api.env.existingSecret` | `basin.env.existingSecret` |
| `api.env.disableRegistration` | `basin.env.disableRegistration` |
| `api.env.disablePasswordRegistration` | `basin.env.disablePasswordRegistration` |
| `api.env.database` | `basin.env.database` |
| `api.livenessProbe` | `basin.livenessProbe` |
| `api.readinessProbe` | `basin.readinessProbe` |
| `web.*` | removed, web is bundled in the basin image |

### Example values migration

**Before (`values.yaml`):**
```yaml
api:
  image:
    repository: ghcr.io/usebasin/api
    tag: "2.5.0"
  service:
    type: ClusterIP
    port: 1337
  env:
    clientUrl: "https://basin.example.com"
    authSecret: "your-secret-here"

web:
  image:
    repository: ghcr.io/usebasin/web
    tag: "2.5.0"
  service:
    type: ClusterIP
    port: 5173
```

**After (`values.yaml`):**
```yaml
basin:
  image:
    repository: ghcr.io/usebasin/basin
    tag: "2.6.0"
  service:
    type: ClusterIP
    port: 5173
  env:
    clientUrl: "https://basin.example.com"
    authSecret: "your-secret-here"
```

### Upgrade command

```bash
helm upgrade basin basin/basin \
  --version 0.3.0 \
  --values your-values.yaml \
  --namespace basin
```

If you store values in a file, update the keys before running the upgrade. Helm will reject unknown keys and the deployment will fail if `api.*` or `web.*` keys remain.

## Minimum working configuration

After upgrading, a minimal `.env` for Docker Compose requires three values:

```env
BASIN_CLIENT_URL=http://localhost:5173
POSTGRES_PASSWORD=changeme
AUTH_SECRET=replace_with_output_of_openssl_rand_hex_32
```

Generate a stable secret with `openssl rand -hex 32` and keep it persistent, or active sessions will be invalidated after a container restart.

`POSTGRES_DB` and `POSTGRES_USER` default to `basin` if not set. `BASIN_API_URL` and `DATABASE_URL` are derived automatically.
